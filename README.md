# BrandOS

Дашборд владельца бизнеса, который продаёт на Wildberries и Ozon. Реализован первый этап из документа «Сборка BrandOS»: интерфейс на демонстрационных данных. Дополнительно работают центр решений на встроенных правилах, ОПиУ, ДДС, РНП, юнит-экономика и генератор черновиков деклараций по шаблону.

## Запуск

Нужен Node.js 20 или новее. Для запуска приложения установка пакетов не требуется:

```sh
npm start
```

Сервер использует порт `3000`. Параметры: `PORT=3001 HOST=127.0.0.1 npm start`. Проверка сервиса: `curl -f http://127.0.0.1:3000/health` — `{"status":"ok","mode":"demo"}`.

Можно открыть `index.html` непосредственно в браузере. CSS, JavaScript, SVG-графики и шрифт Inter встроены в файл; CDN и внешние запросы для интерфейса не нужны. Сохранение в режиме `file://` зависит от браузера, поэтому для постоянной работы рекомендуем локальный сервер.

## Что работает

- Все 17 разделов меню, адаптивное меню, глобальный поиск, настройки бизнеса и профиля.
- Главная: приветствие по московскому времени, четыре KPI, мини-графики, план месяца, факт и прогноз денег на 30 дней с условным коридором неопределённости и кассовым разрывом, маржа по каналам, платежи, дебиторка, продажи и склад.
- Задачи: создание, редактирование, приоритет, срок, исполнитель, фильтры, drag-and-drop и доступная альтернатива через выбор статуса.
- Документы: фильтры источника и статуса, карточка документа, загрузка файлов до 10 МБ, скачивание оригинала, локальная отметка проверки и создание связанной задачи.
- Центр решений: рекомендации по остаткам, ДРР, кассовому разрыву и документам. Принятие создаёт отдельную задачу на каждый шаг; после завершения задач решение переходит в выполненные. Отложить на 3 дня, отклонить с причиной, вернуть и обсудить с ассистентом.
- Аналитика: только показатели товаров, с фильтрами дат и канала. Рекламные кампании и внешний трафик находятся в разделе «Реклама»; трафик, конверсия и экспорт учитывают выбранный период.
- Общий календарь: сегодня, вчера, последние 7 дней, текущий месяц и свой диапазон включительно. Выбор сохраняется между разделами и перезагрузками; доступен год демо-истории.
- ОПиУ: выручка, комиссии, логистика, себестоимость, валовая прибыль, реклама, постоянные расходы и прибыль до налога. Сравнение с предыдущим периодом той же длины.
- ДДС: операции выписки, поступления, выплаты, чистый денежный поток, остатки на начало и конец. Плановые платежи и прогноз сюда не включаются.
- РНП и юнит-экономика: только названия колонок из документов, единая таблица со всеми колонками, закреплённый артикул продавца, карточки товаров и источники значений. Данные ожидаются от API или заказчика; примеров и формул Excel нет.
- Юнит-экономика: 19 исходных названий колонок и артикул продавца, все показатели в одной таблице с горизонтальной прокруткой и закреплённым артикулом продавца. Ручные уточнения отделены от API.
- Налоги: генерация текстового черновика УСН «Доходы» / «Доходы минус расходы», редактируемая ставка, реквизиты, годовые суммы, авансы, предпросмотр, TXT-скачивание и сохранение в документы. Поддерживается собственный TXT-шаблон с полями `{{company}}`, `{{inn}}`, `{{tax}}` и другими.
- Склад: остатки по складам WB/Ozon, карточки складов, фильтры маркетплейса, склада и артикула; отдельно доступно, резерв, к покупателю и возвраты. Серверный `/api/inventory` принимает нормализованный снимок через `INVENTORY_SNAPSHOT_PATH`; без настройки используется явно помеченное демо. Имена и ID реальных складов должны поступать из кабинетов. См. [подключение остатков](docs/inventory-integration.md).
- CRM удалена из навигации, главной, поиска, быстрых действий и интеграций. Ранее сохранённые локальные сделки не стираются автоматически.
- Финансы, продажи, маркетплейсы, реклама, склад, поставки, налоги и интеграции имеют собственные рабочие экраны.
- CSV-экспорт задач, документов, аналитики, остатков, банковской выписки, платежей, ОПиУ и ДДС; РНП и юнит-экономика выгружаются в XLSX. Формулы из пользовательского ввода экранируются.
- Боковой демо-ассистент отвечает по встроенным правилам о данных текущего пространства. Горячие клавиши: Ctrl/Cmd+K — поиск, Ctrl/Cmd+J — ассистент, Escape — закрыть панель.

## Хранение и демо-ограничения

Вся начальная модель находится в объекте `data` в `index.html`. Задачи, архив ранее созданных сделок, документы, решения, профиль и настройки сохраняются в `localStorage` (`brandos-demo-v1`); оригиналы загруженных файлов — в IndexedDB (`brandos-files`). После очистки данных сайта локальные изменения будут потеряны. Разные браузеры и пользователи не разделяют данные.

Все финансовые цифры, история, прогноз, источники и документы-примеры демонстрационные. Кнопка обновления пересчитывает локальную модель; сетевой синхронизации нет. Период считается из дневных демонстрационных записей. Месячные исходные суммы распределяются по датам детерминированно. План на главной относится к текущему месяцу. РНП и юнит-экономика используют только названия колонок документов; показатели ожидаются от API или заказчика. Прибыль — до налога; реклама учтена отдельно от удержаний маркетплейсов. История банковской выписки содержит только четыре операции за последние три дня, что явно обозначено в ДДС. Изменения себестоимости, плана, расходов и лимита ДРР влияют на соответствующие расчёты. Некоторые тренды и внешний трафик остаются фиксированными примерами; маржа каналов пересчитывается по дневной модели.

Налоговый генератор создаёт **расчётный черновик**, а не официальный бланк или XML ФНС. Формат декларации и актуальный шаблон ещё не предоставлены пользователем. Годовые суммы вводятся вручную и не подменяются выборкой за текущие даты; налоговые вычеты, льготы, убытки прошлых лет, поквартальная история и изменения ставок не моделируются. Для подачи необходима проверка бухгалтером и актуальная официальная форма.

Ассистент не вызывает внешнюю модель. Текст файлов не распознаётся; суммы и контрагенты загруженных файлов не выдумываются. Отметка документа проверенным не подписывает его в ЭДО и не проводит платёж. Поставки не отправляются во внешние сервисы.

В следующем этапе нужны серверная БД, коннекторы и безопасные переменные окружения. Ключи в интерфейсе не запрашиваются. Для ИИ предусмотрено направление OpenAI вместо Claude. Реальные интеграции, общий доступ команды и вход по паролю ещё не реализованы. Для просмотра без установки подготовлена статическая демосборка; включение публичного хостинга выполняется отдельно. Текущий демонстрационный сервер предназначен для разработки.

## Проверка

Быстрая проверка синтаксиса:

```sh
npm run check
```

Браузерные тесты:

```sh
npm ci
npx playwright install chromium
npm test
```

Если Chromium уже установлен, используйте `CHROMIUM_PATH=/usr/bin/chromium npm test`. При проблемах с правами npm можно задать `npm ci --cache /tmp/brandos-npm-cache`.

Проверки `npm run test:unit` выполняются на порту 3500: API-данные и ручные уточнения, происхождение, отсутствие примеров, периоды, XLSX, компактные таблицы и WCAG при ширинах 1280/768/375. Общие браузерные проверки охватывают 17 разделов на 1280/768/375, отчёты и остатки. Артефакты находятся в игнорируемом `test-results/`.

## Структура

- `index.html` — весь интерфейс, стили, данные, логика и встроенный шрифт.
- `server.mjs` — Node.js HTTP-сервер без фреймворков; приложение, `/health`, `/api/inventory`, `/api/rnp` и `/api/economics`.
- `lib/rnp-reconciliation.mjs` — приоритет недельных отчётов и журнал версий РНП; `lib/rnp-store.mjs` — атомарный импорт и серверное чтение; `npm run test:rnp` проверяет сверку и серверное хранение.
- `lib/inventory.mjs` — проверка публичного формата остатков.
- `fixtures/inventory-demo.json` — явно помеченные примеры складских остатков.
- `docs/inventory-integration.md` — договорённости о будущем подключении WB/Ozon и ограничения проверки справочника.
- `scripts/check.mjs` — проверка синтаксиса.
- `scripts/browser-test.mjs` — сценарии в Chromium и axe.
- `scripts/reports-test.mjs` — финансовые расчёты, календарь и шаблоны деклараций.
- `scripts/economics-test.mjs` — данные API и заказчика, отсутствие содержимого Excel, экспорт и компактные таблицы.
- `.agents/skills/` — установленные навыки Codex.
- `.ux-profile.md` — принятые правила дизайна.
- `LICENSE-Inter.txt` — лицензия SIL Open Font License на шрифт Inter.


## Юнит-экономика: данные из источников

Из документов сохранены только названия колонок в `fixtures/economics-columns.json`; их содержимое и формулы не используются. Все таблицы используют общий компонент и стили. Все колонки видны в единой таблице с горизонтальной прокруткой: ползунок сверху, стандартная полоса прокрутки, Shift + колесо мыши или свайп. Артикул продавца закреплён слева на всех экранах. Поиск, фильтр маркетплейса и страницы по десять товаров сохраняют компактность. Позиция прокрутки левого меню сохраняется при перезагрузке и обновлении интерфейса.

Без подключения API эти вкладки пустые. Для проверенного источника сервер читает `ECONOMICS_SNAPSHOT_PATH` через `/api/economics?from=…&to=…`. Неизвестные показатели отмечены «—». Доступные в API значения имеют приоритет; недоступные запрашиваются у заказчика и сохраняются отдельно. При подключении запросить файл закупочных цен и налоговые параметры. Прямые коннекторы WB/Ozon пока не реализованы; кнопка обновляет только настроенный серверный источник.

Подробнее: [контракт и поведение](docs/economics-integration.md), [сверка РНП](docs/rnp-reconciliation.md). Проверка: `CHROMIUM_PATH=/usr/bin/chromium npm test`.

В РНП восстановлены многоуровневые шапки из исходного документа: основные блоки и подколонки логистики/хранения. Блоки и модели продаж в сравнении разделены цветами. Порядок начинается с артикула продавца, группы и товара; штрих-коды убраны. В юнит-экономику добавлен артикул продавца, а столбцы окрашены серым, светло-серым и светло-фиолетовым согласно указанию владельца. Экспорт сохраняет группировку, цвета и закрепление артикула.

Числовые колонки РНП/юнит-экономики автоматически подгоняются под самое длинное число во всей выборке; текст и заголовки переносятся. Вместо названия в таблице показана миниатюра обложки из `coverUrl` источника. Название доступно по наведению/в карточке и сохраняется в XLSX. Пока каталог API не подключён либо фото недоступно, отображается заглушка; произвольные изображения и ссылки по артикулу не придумываются.

## Демо для заказчика без установки

`npm run build:demo` собирает `dist/` только из публичного интерфейса, встроенного шрифта и заранее определённых демонстрационных JSON. Сервер, каталог `data`, пользовательские файлы и секреты в публикацию не копируются. Реальные API в статической версии не вызываются. Юнит-экономика и РНП сохраняют согласованное пустое состояние до подключения кабинетов. Изображения по отменённой просьбе не добавлялись.

Проверка: `CHROMIUM_PATH=/usr/bin/chromium npm run test:demo`. Локальный просмотр собранной версии: `npm run preview:demo`. Сборка работает из подкаталога GitHub Pages и использует локальные JSON-файлы вместо серверных API.

`npm run publish:demo` публикует только эту сборку в ветку `gh-pages`. Скрипт не меняет видимость репозитория и не включает Pages через GitHub API. Для существующей ветки требует маркер `.brandos-demo`, сохраняет историю и выполняет обычный push без force.

Владелец репозитория один раз выбирает **Settings → Pages → Build and deployment → Deploy from a branch → gh-pages → /(root) → Save**. После успешного развёртывания GitHub покажет действующую ссылку. Предполагаемый адрес для этого репозитория: `https://truvasvas.github.io/pult_upravleniya/`. Сам факт отправки ветки не подтверждает работоспособность адреса: нужно дождаться сообщения о публикации и проверить доступ без входа. В текущей облачной среде GitHub REST API блокируется сетевым прокси (CONNECT 403), поэтому включение хостинга нельзя считать выполненным автоматически.
