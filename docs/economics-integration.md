# Юнит-экономика и РНП: только названия колонок из документов

## Указание владельца

Из присланных документов используются **только названия колонок**. Товары, цифры, формулы, тарифы и налоговые допущения из Excel не являются данными кабинета и не участвуют в расчёте. Предыдущие локальные сценарии сохранены в браузере для сохранности, но больше не читаются этими вкладками. Загруженные оригиналы находятся вне checkout; копии с данными и контрольные значения старого калькулятора удалены из репозитория. Единственная схема — `fixtures/economics-columns.json`.

Показатели, доступные в API маркетплейсов, нужно получать оттуда. Если конкретный показатель источник получить не может, его необходимо запросить у заказчика. При подключении кабинетов запросить у владельца файл закупочных цен с артикулами, у селлера — налоговый режим и ставку. Не принимать «6+1%» из названия колонки за подтверждённую налоговую ставку.

## Интерфейс

«Юнит-экономика» сохраняет 19 названий колонок SELLER MOON. «РНП» сохраняет колонки листов «Товары», WB FBW, WB FBS, Ozon FBO, Ozon FBS, «Сравнить». Все вкладки используют общий `table()` / `.data-table`: одинаковые фон, шрифт, выравнивание и отступы со всеми таблицами дашборда. Нет редактирования в ячейках, букв Excel, многоэтажных заголовков или цветных полей калькулятора.

По умолчанию видны основные показатели. Переключатель групп открывает остальные колонки (не более шести за раз). На узком экране видны товар и два показателя; все колонки доступны через карточку товара. Таблица использует ширину контейнера, шрифт не уменьшается для размещения всех колонок. Поиск, фильтр маркетплейса и страницы по 10 товаров ограничивают размер представления. Экспорт содержит все колонки и строки выбранного набора, независимо от группы и страницы; фильтры товара/МП и период сохраняются.

В карточке показаны значение, источник, статус подтверждения и ссылка на отчёт/метод расчёта. Неизвестное значение — «—», явный ноль — число. Отсутствие поля не означает нулевые расходы. В исходных данных интерфейса нет закупочных цен, налоговых ставок, тарифов или формул.

## Источник сервера

Прямые коннекторы WB/Ozon ещё не подключены: ключи отсутствуют, проверенное сопоставление актуальных API и полей не выполнено. Поэтому интерфейс по умолчанию пустой, без выдуманных товаров. Кнопка обновления получает **подготовленные сервером данные**, не вызывает ещё не реализованный коннектор маркетплейса.

`GET /api/economics?from=YYYY-MM-DD&to=YYYY-MM-DD` читает `ECONOMICS_SNAPSHOT_PATH` и проверяет контракт. Переменная задаётся серверу; `.env` автоматически не загружается. Без переменной — `mode: disconnected`, `rows: []`. При ошибке источника — 503; интерфейс сохраняет последний успешный снимок. Результаты за другой период не отображаются. Если источник не содержит выбранный диапазон, возвращается пустой список за этот диапазон. Просроченный ответ на другой запрос не заменяет текущий диапазон.

Сервер и браузер применяют один валидатор `lib/economics-schema.mjs`. Неизвестные поля исключаются; ключи/секреты источника не передаются. HTTP-запись закрыта. Исходный JSON должен быть сформирован проверенным адаптером; этот внутренний контракт не является форматом ответа WB/Ozon.

```json
{
  "version": 1,
  "mode": "source",
  "from": "2026-10-01",
  "to": "2026-10-20",
  "updatedAt": "2026-10-20T10:00:00Z",
  "rows": [{
    "view": "unit",
    "marketplace": "wb",
    "accountId": "seller-account-id",
    "externalId": "marketplace-product-id",
    "article": "seller-article",
    "name": "Название из каталога",
    "values": {},
    "unavailable": []
  }]
}
```

`view`: `unit`, `products`, `wb-fbw`, `wb-fbs`, `ozon-fbo`, `ozon-fbs`, `compare`. Строка идентифицируется набором `(view, marketplace, accountId, article)`. Поля разных кабинетов и моделей не смешиваются; для сравнения моделей требуется отдельное проверенное сопоставление товаров, а не совпадение названия.

`name`, `article`, `group`, `barcode` — метаданные каталога; `group` и `barcode` допускают отсутствие. Ключи числовых значений перечислены в `fixtures/economics-columns.json`. Каждое значение содержит:

- `value`: конечное число, рубли за единицу либо процентные пункты (25 означает 25%, не 0.25).
- `source`: `api` или `calculated`.
- `reference`: идентификатор отчёта / документированного источника.
- `at`: время источника, ISO timestamp.
- `status`: `current`, `daily-preliminary` или `weekly-confirmed`.
- `method`: обязательное описание согласованной методики для `calculated`.

Формулы не копируются из Excel. Если метрика требует вычисления, адаптер должен передать проверенный результат с методикой; нельзя заменить общий финансовый итог тарифом за единицу или вычислить прибыль при неизвестных расходах. Для отсутствующего значения не передавайте поле: интерфейс покажет «—». Если адаптер установил, что колонка недоступна через API, добавьте её ключ в `unavailable`; она появится в запросе заказчику. Одновременно передать значение и отметить его недоступным нельзя.

## Данные заказчика

Закупка и собственные затраты, налоговая ставка и поля, явно отмеченные источником как недоступные, можно уточнить через карточку товара. «Нужны данные» формирует список по артикулам, который можно скачать TXT для заказчика; система не отправляет сообщения от имени пользователя.

Значения заказчика хранятся отдельно в `data.economics.manual` / localStorage, с датой ввода и идентификатором строки. Обновление API не стирает эти записи. Если источник впоследствии вернёт подтверждённое значение этой колонки, оно имеет приоритет; поле API нельзя заменить через форму ручного ввода. Ручные значения не становятся подтверждёнными недельным отчётом автоматически.

XLSX-экспорт содержит значения и лист происхождения. Неизвестные ячейки пустые, проценты форматируются как проценты; формул Excel и значений по умолчанию нет. Строковые значения экспортируются как текст, не как исполняемые формулы.

## Сверка ежедневных и недельных отчётов

Существующий журнал `/api/rnp`, импорт `npm run rnp:import` и модуль приоритета закрытых недельных отчётов сохранены. В РНП они доступны в «Фактических данных». Этот журнал не превращается автоматически в тарифы юнит-экономики: сначала необходимо проверить артикул, модель, дату, количество и единицы измерения. См. [правила сверки](rnp-reconciliation.md).

## Проверка

`npm run test:unit` проверяет отсутствие примеров и формул, изоляцию старых сценариев, контракт и происхождение данных, неизвестные/нулевые значения, приоритет API, запросы заказчику, сохранение ручных значений, разные МП, периоды, страницы, ошибки источника, XLSX и представления на 1280/768/375. Общий `npm test` проверяет также 17 разделов дашборда, остальные отчёты, остатки и сверку РНП.
