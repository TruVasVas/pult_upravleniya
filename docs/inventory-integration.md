# Остатки по складам Wildberries и Ozon

В интерфейсе доступны карточки складов, остатки по товарам, фильтры маркетплейса/склада/артикула, отдельные количества доступного товара, резерва, движения к покупателям и возвратов. Снимок — состояние на конкретное время, календарь продаж его не пересчитывает.

## Проверка справочников

20 октября 2026 года обращения к официальной документации были заблокированы прокси среды: `Tunnel connection failed: 403 Forbidden`. Поэтому текущие названия и актуальные методы API **не подтверждены по официальному каталогу**. Новые адреса методов не угадываются и сетевые коннекторы пока не реализованы.

Ссылки для проверки перед подключением:

- WB API: https://dev.wildberries.ru/openapi/analytics
- WB API, отчёты: https://dev.wildberries.ru/openapi/reports
- WB API, поставки и справочники: https://dev.wildberries.ru/openapi/supplies
- Кабинет WB, инструкции: https://seller.wildberries.ru/instructions/ru/ru/
- Ozon Seller API: https://docs.ozon.ru/api/seller/
- Ozon, склады FBO: https://docs.ozon.ru/global/fulfillment/fbo/warehouses/

Для доступа к этим источникам в черновике облачной среды добавлены `dev.wildberries.ru`, `seller.wildberries.ru`, `docs.ozon.ru`; настройки нужно сохранить и опубликовать в интерфейсе среды. Это не подключает кабинеты и не передаёт ключи.

В демонстрационном файле приведены **примеры**: WB — Коледино, Электросталь, Казань; Ozon — Хоругвино, Софьино, Пушкино. Это не полный или проверенный справочник и не список складов конкретного продавца. У них `externalId: null`, а внутренние ключи начинаются с `demo-`. Реальные числовые ID не придуманы.

## Подготовленная точка подключения

`GET /api/inventory` отдаёт публичные поля проверенного JSON-снимка. Без настройки сервер читает `fixtures/inventory-demo.json`, режим — `demo`. Чтобы подставить результат будущего серверного коннектора:

```sh
INVENTORY_SNAPSHOT_PATH=/absolute/path/to/inventory.json npm start
```

Файл должен быть сформирован самим коннектором/импортом. Сервер не получает данные WB/Ozon автоматически. Заменяйте файл атомарно после успешной загрузки полного снимка. Клиент обновляет показанные остатки по кнопке «Обновить остатки». Ошибка сети или структуры оставляет последний успешно показанный снимок.

Пример структуры (значения ID — обозначения, их нужно заменить реальными ID источника):

```json
{
  "version": 1,
  "mode": "live",
  "updatedAt": "2026-10-20T12:00:00Z",
  "warehouses": [
    {
      "key": "wb:FBW:warehouse-id-from-source",
      "marketplace": "wb",
      "externalId": "warehouse-id-from-source",
      "name": "Название ровно из ответа маркетплейса",
      "fulfillment": "FBW"
    }
  ],
  "items": [
    {
      "warehouseKey": "wb:FBW:warehouse-id-from-source",
      "marketplace": "wb",
      "article": "Артикул продавца",
      "name": "Название товара",
      "available": 10,
      "reserved": 2,
      "toCustomer": 1,
      "returnsInTransit": 0
    }
  ]
}
```

Все количества — целые неотрицательные числа. В live-режиме каждому складу обязателен непустой `externalId`, полученный от источника. Идентичность склада определяется сочетанием маркетплейса, модели и externalId, а не названием. В таблице одна запись на склад и артикул; размеры/штрихкоды необходимо агрегировать на сервере, иначе дубли будут отклонены. Внутренние названия полей не являются заявлением об актуальной схеме внешнего API.

Клиентские и серверные проверки отвергают неизвестные склады, несоответствие маркетплейса, отрицательные количества, повторные пары склад/артикул и отсутствующие live-ID. Сервер отправляет только явно перечисленные складские поля; дополнительные поля исходного файла не попадают в ответ.

## Требования к будущим коннекторам

1. **WB FBW:** получить актуальный каталог складов и остатки; сохранить официальное название, связать склад с warehouseID из справочника. Если отчёт содержит только warehouseName, выполнять сопоставление на сервере, а не придумывать ID. Собственные склады FBS — отдельная модель, не каталог складов WB.
2. **Ozon FBO:** использовать warehouse_id и warehouse_name из актуального источника остатков/каталога FBO; сопоставить SKU и offer_id с артикулом продавца. Метод списка собственных складов продавца FBS не заменяет каталог центров FBO.
3. Разобрать доступное, резерв, отгрузки и возвраты по определениям актуального API. Не вычитать резерв повторно из уже доступного количества и не приравнивать неопределённое поле к резерву по названию.
4. Обрабатывать пагинацию до конца, лимиты и ошибки авторизации. При сбое одной страницы не заменять полный снимок частичным результатом. Не смешивать реальные и демонстрационные остатки.
5. Токены находятся только на сервере, с минимальными правами чтения; ключи не вводятся в браузере и не записываются в логи. Реальное подключение проверяется после предоставления доступа, отдельной задачей.

Сервер предназначен для разработки. Общий доступ команды и защита входа требуют отдельного этапа перед публикацией реальных бизнес-данных.
