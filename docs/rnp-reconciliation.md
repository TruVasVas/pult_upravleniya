# Сверка РНП: ежедневные и закрытые недельные отчёты

Из Excel теперь используются **только названия колонок**. Формулы, товары, тарифы и налоговые допущения удалены. Актуальная схема и интерфейс описаны в [подключении юнит-экономики](economics-integration.md). Старое описание калькулятора из Excel больше не применяется.

Пользователь просит получать доступные данные из API маркетплейсов, остальные запрашивать у заказчика. При подключении запросить файл закупочных цен и налоговые параметры; до получения данных показывать пропуски. API кабинетов ещё не подключены. Независимая сверка нормализованных финансовых отчётов сохранена ниже; её результаты нельзя без сопоставления превращать в тарифы на единицу.

## Правила модуля

1. Ключ ячейки: маркетплейс + кабинет + дата + артикул (или `null` для общего итога кабинета) + показатель. Данные разных кабинетов, маркетплейсов и метрик не смешиваются.
2. Ежедневные значения — `daily-preliminary`. Новая версия ежедневного источника заменяет прежнюю предварительную версию, а не прибавляется к ней.
3. Детализированный закрытый недельный отчёт имеет приоритет по тем ячейкам, которые он действительно подтверждает. Получение более позднего ежедневного отчёта не перезаписывает подтверждённые недельные значения.
4. Для каждого изменения записываются значения до/после, отчёт, версия, источник, время импорта, разница и причина. Даже одинаковые суммы могут менять статус происхождения с ежедневного на подтверждённый недельный.
5. Повторный импорт идентичного отчёта той же версии идемпотентен. Другая сумма под тем же ID и revision запрещена: требуется новая версия. Все предыдущие отчёты остаются в журнале.
6. Если маркетплейс выпустит корректировку закрытого отчёта, она принимается новой revision. Для замены отчёта другим ID требуется явная ссылка `supersedes` на прежний отчёт того же кабинета и периода. Неоднозначные пересекающиеся недельные отчёты и циклы корректировок отвергаются.
7. Недельный отчёт должен быть закрыт и содержать значения по реальным датам. Один общий недельный итог не распределяется равномерно по дням. Нулевые суммы должны быть явно переданы источником; неизвестные значения не превращаются в ноль.
8. Недельная версия, из которой исчезла ранее известная ячейка, помечает её `needs-review` с `null`. Старая ежедневная сумма не восстанавливается автоматически. Метрики, никогда не подтверждавшиеся недельным отчётом, остаются предварительными до получения подходящего источника.
9. Модуль работает с полными снимками ячеек, не с отдельными строками денежных операций. Будущий коннектор обязан забрать все страницы, устранить дубли по ID исходных операций и агрегировать их до передачи. Неуспешная/частичная выгрузка не должна считаться полным отчётом.

Закрытая неделя — основной источник для сверки, но не гарантия отсутствия будущих корректировок от площадки. Периодичность и статус окончательного финансового документа проверяются отдельно для WB и Ozon; произвольный документ Ozon нельзя назвать недельным только ради единой модели.

## Пример нормализованной версии

```js
{
  id: 'ID-отчёта-из-источника',
  marketplace: 'wb',
  accountId: 'ID-кабинета',
  source: 'weekly',
  revision: 1,
  from: '2026-10-12',
  to: '2026-10-18',
  closed: true,
  publishedAt: '2026-10-19T09:00:00Z',
  cells: [{date:'2026-10-12',article:'Артикул',metric:'revenue',value:92}]
}
```

Названия метрик в примере технические; они не заменяют карту реальных колонок пользовательского Excel. Схема внешнего API не угадывается по этому примеру.

## Импорт и серверное хранение

`lib/rnp-store.mjs` сохраняет нормализованные полные отчёты атомарно: блокировка импорта, проверка всего пакета до записи, временный файл с правами 0600, резервная копия `.bak`, затем rename. Повторный импорт не меняет файл. При чтении исходные отчёты повторно проверяются и сверяются; сохранённым вычисленным ячейкам сервер не доверяет. Каталог `data/` игнорируется Git.

```sh
# Команды выполняются в корне проекта. Используйте один абсолютный путь.
export RNP_LEDGER_PATH=/workspace/pult_upravleniya/data/rnp-ledger.json
npm run rnp:import -- /path/to/normalized-reports.json
npm start
```

Вход — один нормализованный отчёт из примера выше или массив отчётов. Это не импорт произвольного финансового XLSX маркетплейса. `GET /api/rnp` отдаёт сверенные ячейки, историю изменений и историю импортов без ключей API. Без пути — пустой статус `disconnected`. При ошибке чтения/проверки — 503, интерфейс сохраняет последний успешный снимок. HTTP-запись не открыта. Нажатие «Обновить отчёты» читает серверный журнал и **не запускает запрос в кабинет**.

Сервер разработки не имеет авторизации. Перед публикацией финансовых данных необходимы аутентификация и разграничение доступа; сам журнал не следует размещать в открытом репозитории.

## Следующее подключение

Прямые коннекторы и планировщик не реализованы. При подключении запросить файл закупочных цен у владельца и налоговые параметры у селлера, проверить актуальные официальные API и полную выгрузку операций. Для всех показателей важны отдельные модели продаж, кабинеты, даты и количества. Нельзя передавать общий финансовый итог как цену или тариф на единицу.

## Проверка

`npm run test:rnp` проверяет правила приоритета, версии, атомарный импорт, откат пакета, идемпотентность, CLI и ошибки источника. `npm run test:unit` проверяет общий интерфейс юнит-экономики/РНП и данные без содержимого Excel.
